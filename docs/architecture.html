벡터 저장소 3종 아키텍처

OpenShift AI 3.4의 Llama Stack이 pgvector / FAISS / Qdrant 세 벡터 저장소를 어떻게 같은 API 뒤에서 갈아끼우는지 보여주는 다이어그램입니다. 브라우저(챗 UI)와 CLI(데모 스크립트) 두 클라이언트가 완전히 동일한 호출로 세 백엔드에 접근합니다.

요청 흐름 — 브라우저에서 질의 하나를 입력했을 때

  1. chat-ui가 /api/search로 질의를 받는다.
  2. 같은 함수가 pgvector / FAISS / Qdrant 세 서비스에 동시에 vector_stores.search(search_mode=...)를 호출한다 — 코드는 세 트랙 모두 동일하다.
  3. 각 트랙은 자기 백엔드에서 검색한다: pgvector는 SQL로, FAISS는 파드 내부 인덱스에서, Qdrant는 자신의 엔진에서(요청한 모드가 vector면 벡터만, keyword/hybrid면 어휘 점수까지 결합).
  4. 세 결과를 카드 3개로 모아 브라우저에 반환한다 — Qdrant 카드는 vector/keyword/hybrid 탭을 눌러 같은 데이터를 다른 모드로 다시 볼 수 있다.
